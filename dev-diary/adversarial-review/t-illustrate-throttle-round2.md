## Items probed and found sound (not findings)

- **Pacer arithmetic.** Slots are at least 31.5 s apart, so any 60 s window holds at most two reserved slots; the 5% margin (1.5 s) absorbs timer lateness. A quiet spell correctly resets the queue (first caller goes at once; the second waits one interval), so there is no catch-up burst: `p.next` only moves forward from `max(next, now)`. `time.Now` carries the monotonic reading through `Add`/`Sub`. `rpm` above 60e9 yields interval 0, i.e. unpaced, rather than overflow; negative is unpaced; `base/20` of a tiny base is 0, harmless.
- **Deadlock and starvation.** The mutex covers only the slot arithmetic and is released before sleeping. Slots are handed out in arrival order, so no caller starves; a queued caller whose context ends leaves its slot spent (documented, errs sparse). `refLimit = min(refLimit, limit)` is at least 1; no nested errgroup. Cancelled pacer waits return the context error alone and are not retried (`throttled` is false for it).
- **Interaction of pacer, retry, MaxWait and ReferenceLimit.** The retry loop re-enters the pacer on every attempt, so a 429 retry cannot burst; pacer queue time is not charged to `MaxWait` (documented); with provider retry-afters of 80-90 s `MaxWait = 5 min` ends the call after four attempts rather than six, which is the intended bound. `ReferenceLimit` is now purely an in-flight bound.
- **Worst-case duration versus proxies.** A default book needs at least (images - 1) x 31.5 s: 8 pages + 2-3 sheets is about 5-5.5 minutes of pacing, and with T7's maximum of 2 regenerations per page (27 images) about 14 minutes, plus backstop waits. Nothing in `bookgen`, `job` or `cmd` imposes a run deadline (`grep WithTimeout` only finds the shutdown context), the SSE route pings every 15 s (`stream/sse.go`), so Cloudflare's 100 s idle limit is not approached and the front end has no client-side timer that declares failure. `app.js`'s "takes a few minutes" copy is now conservative-to-wrong for the worst case; it is T9's file, outside this seam, and not a falsifiable claim, so it is recorded here for the orchestrator rather than counted. The remediation also flagged it.
- **Retry classification and sentinels.** Only `ErrRateLimited` and `ErrTransient` are waited on, separate budgets, a both-wrapped error counts as rate limited; exhaustion text is class-correct and wraps with `%w`. The media client's context-loses-its-chain quirk (`%v` of the transport error) is covered by the `ctx.Err()` check before the budget test. `retryAfter` clamps before multiplying and never returns a negative.
- **Config edge cases.** `Backoff` above `MaxThrottleBackoff` is not clamped on the first wait (only after doubling), contradicting the field's "capped" wording only for absurd values; `MaxWait` still bounds it. Unreachable from production (nothing sets it), so not counted.
- **Test hygiene.** `TestMain` overwrites `defaultSleep` and `realSleep` is tested directly; `TestIllustrate_NoSecondRetryLayer` was correctly replaced by the throttle budget tests; no `os.Setenv`; the simulation's virtual clock cannot hide a pacing bug (late wake-ups only space requests further) and ran 20 times race-clean.
- **Out-of-seam observation (not counted):** `internal/audio/audio.go:99` still says "this package adds no second layer", which `audio/throttle.go` contradicts. Pre-existing; route to T8's owner.
