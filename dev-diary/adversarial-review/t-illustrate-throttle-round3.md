## Items probed and found sound (not findings)

- **Registry key collisions and growth.** Key is `(model, rpm)`; `Config.Model` defaults before `pacerFor`, so "" and `DefaultModel` collide into one key, as they should. Distinct rpm for one model gets two pacers (documented). The key set is bounded by configured models and rates (one in production); no goroutine, timer or file hangs off an entry. No unbounded growth.
- **First-creator-clock-wins.** Reachable only for a caller that passes a `registry` (unexported, tests only): production sets neither `Sleep` nor `Now`, so every production run shares the real clock. A caller that sets only `Sleep` or only `Now` gets a private pacer, which is the safe direction.
- **Lock ordering and races.** `pacerRegistry.mu` is taken and released inside `get`, which then never touches `pacer.mu`; `pacer.mu` covers slot arithmetic only and is released before the sleep. No nested acquisition, no goroutine holding either across I/O. `go test -race` clean in every run; `TestPacerRegistry_ConcurrentGetIsOnePacer` runs 32 callers.
- **Starvation.** Slots are issued in arrival order and a queued caller always gets its own; fan-out per run is 4 pages / 2 sheets, so concurrent books interleave rather than one monopolising the queue. (The strand cost is M2, not starvation.)
- **Test isolation of the global registry.** Tests with a zero or default-rate `ThrottleConfig` resolve into `processPacers` with the real clock and `TestMain`'s instant `defaultSleep`; the pacer's `p.next` therefore drifts forward in real time while nothing ever sleeps, so no test's behaviour depends on what another left in it. Tests that assert waits all inject `Sleep`/`Now` (private) or `RequestsPerMinute: -1` (bypasses every registry). `TestIllustrate_DefaultThrottleRetriesOnTheWire` swaps `defaultSleep` but is unpaced, so it creates no registry entry that could capture the swapped recorder. `-shuffle=on -count=3` run three times: the only failure was the jitter flake (M3), not ordering.
- **Production path.** `cmd/thutapi/main.go:637` builds `bookgen.Config` with no `ImageThrottle`; `bookgen/pipeline.go` forwards it verbatim; `resolve` passes the *raw* `cfg.Throttle` to `pacerFor`, so production resolves to `processPacers` (correct today; unpinned, see M1). `bookgen.Handler` is the only `illustrate.Illustrate` caller (`grep` over non-test code), and the CLI `complete-books` path does not illustrate.
- **Worst-case wall time vs deadlines.** Nothing in `bookgen`, `job` or `cmd` bounds a run (`WithTimeout` only in the media/text clients per call, the 10-minute poll, and shutdown). The pacer wait happens *before* the media call, so it is not charged to the media client's per-call or poll timeouts. A book is at least (images - 1) x 31.5 s (about 5-5.5 min; up to about 14 min with T7's maximum regenerations); with the pacer shared, N concurrent books take about N times that, up to `job.DefaultLimit` = 16. The SSE route pings every 15 s, so Cloudflare's 100 s idle limit is not approached. `static/app.js`'s "a few minutes" copy is now optimistic under load; it is T9's file, outside this seam, already recorded by round 2, not counted again.
- **Docs vs behaviour.** The package header, `# Retry` section, `ThrottleConfig` and bookgen's `ImageThrottle` all say "process-wide, per (model, rate)" and the media client's immediate resubmit as the known gap; they match the code. The "errs sparse" claim is true but understates M2. The `audio.go:99` "no second layer" contradiction remains out of seam (T8), as recorded by round 2.
- **Go style (AGENTS).** No `**T`, `*[]T`, `*map`, `*interface`; no `interface{}`; no new `any`; ctx is the first parameter everywhere it appears (`wait`, `realSleep`, `retryThrottled`'s `ctx`, `generate`, `edit`); every exported identifier in the diff has a doc comment starting with its name; no `panic`/`log.Fatal`; every goroutine exits (errgroup, the `vclock` driver closes on `stop`; `Sleep` returns on `ctx.Done()`); the one non-nil-value-with-error check holds (`retryThrottled` returns `nil, err`); errors wrap with `%w` and are matched with `errors.Is` (the `_ =` grep over the new tests and `throttle.go` is clean; the three hits elsewhere pre-date this change).
- **Cancellation semantics.** A cancelled pacer wait returns the context error alone (not retried); a cancelled retry wait wraps both the context error and the provider's; bookgen's `%w` keeps `context.Canceled` visible to `job.Runner`; end-to-end pin verified red under `%v`.
