# T10b remediation round 1

The three H findings from `t10b-round1.md` are addressed below. The C4
consumer is a narrow cross-track contract row: T10b owns the book state
response and its stream URL shape; the existing T9 interview shell consumes
that response during an ended-interview reload.

| # | Where | What | Fix | Pin | Mutation |
|---|---|---|---|---|---|
| H1 | `static/app.js:253-367`; C4 `/book/{id}/state` and `/interviews/{id}/generate/events` | An ended interview reload did not consume C4, re-posted generation, and turned a busy response into the failed screen. | Added a narrow recovery consumer that opens the book SSE stream first, reads one C4 state snapshot, deduplicates approved page numbers, preserves a running race, redirects ready books, and only posts a new run when C4 says no run exists. Busy races are recovered as live runs. EventSource remains open for its built-in reconnect behavior until a terminal event. | `static/browser-test.js:testEndedReloadCatchesUpRunningGeneration` proves an ended reload opens the generate stream before one state read, restores one marker from C4, makes no generate POST, and does not show the failure door. `node --check static/app.js static/browser-test.js`; `go test ./internal/web ./cmd/thutapi -race -count=1`. | Revert the recovery consumer and the browser pin: an ended reload has no `/book/{id}/state` call, repeats `POST /generate`, and renders the false failed screen on a busy run. |
| H2 | `internal/web/web.go:load` and `Download`; `internal/web/web_test.go` running and failed state/page cases | Running or failed latest runs retained prior PDF and MP4 URLs while replacing only old illustration URLs. | Clear `pdfURL` and `videoURL` together with the old illustration map whenever C4 reports `running` or `failed`, so JSON state and server-rendered controls describe only the latest run.
