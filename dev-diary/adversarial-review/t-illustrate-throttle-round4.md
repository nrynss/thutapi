## Items probed and found sound (not findings)

- **Slot arithmetic.** Reviewed `reserve` line by line: slots stay sorted (the candidate only moves forward past a conflicting slot, and is inserted at the first slot it fits before); no two entries are ever closer than the interval (`TestPacer_NoTwoSlotsCloserThanTheInterval`, 2,000 random steps, and the no-gap-fill / no-margin mutations go red); equal slots cannot occur, so `release`'s `Equal` match is unambiguous. Release of a slot that already arrived is refused (mutation red), so a spent slot always spaces its successors. The sliding-window bound holds arithmetically: any three consecutive submissions span at least 2 x 31.5 s = 63 s > 60 s (and (n+1) submissions span n x 1.05 x 60/n s for any rate).
- **Fairness / starvation.** Each caller gets its own slot; gap filling lets a later caller take a slot a cancelled waiter left, but never displaces a held slot, so no queued waiter's slot moves. Fan-out per run is bounded (4 pages / 2 sheets), so concurrent books interleave.
- **Slot-list growth.** Bounded by live waiters plus at most the last interval's slots; expired slots drop on the next reserve (see L2 for the missing pin). Registry keys are bounded by configured models and rates (one in production).
- **Locks.** `pacerRegistry.mu` is released before any `pacer.mu`; `release` reads `p.now()` under `p.mu` (the injected clocks take no pacer lock); no lock is held across a sleep or I/O. `-race` clean in every run.
- **Clock jumps.** Production clock is `time.Now()` (monotonic reading), so `Add`/`Sub`/`After` are immune to wall-clock steps. `realSleep` timer firing before `ctx.Done()` returns nil and the slot has arrived; a context that wins the select after the slot arrived leaves the slot spent (safe direction).
- **Overflow.** `interval = base + base/20`; `base = time.Minute / rpm` cannot overflow, and an rpm above 6e10 yields base 0, which is "unpaced" (not a realistic configuration). `retryAfter` clamps before multiplying; `jitter` and the doubling are capped at `MaxThrottleBackoff`.
- **Backoff 20 s -> 15 s.** Schedule maximum 15 + 30 + 60 + 90 + 90 = 285 s <= `DefaultThrottleWait` 300 s; the constants' docs and the three pins agree (mutation red). No other place cites the default as 20 s: the only `20 *` hits are tests that set `Backoff` explicitly. `internal/audio`, `internal/gmi` and `cmd` are untouched, so audio's own constants are not altered. `gmi/errors.go` says "retry with backoff" / "caller MAY retry again", which the implementation honours; the stale "no second layer" statements in this package were rewritten, and the remaining "never retried here" statements are about the judge, which is true.
- **Production wiring.** `resolve` passes the raw `cfg.Throttle` to `pacerFor`, so production (`cmd/thutapi/main.go` sets no `ImageThrottle`) shares `processPacers`; now pinned (`TestResolve_ZeroThrottleSharesTheProcessPacer`, mutation red).
- **Contract row C1.** Truthful: two pass-through fields forwarded verbatim, harness gains `newPipelineHarnessWith`, the three named pins exist and go red under their mutations, `cmd/thutapi` needs no edit, bookgen coverage 82.5% above its floor. Its "Sanction: none recorded" clause is now an accurate statement of the (absent) sign-off; it remains for the operator to ratify or reject at commit review (process note, not counted).
- **Go style.** No `**T`, `*[]T`, `*map`, `*interface`, `interface{}`, `panic`, `log.Fatal`, `context.TODO` in the added lines; ctx is the first parameter everywhere it appears; every exported identifier added has a doc comment starting with its name; no new `_ =` in the throttle code or tests; goroutines in the tests exit (errgroup, the `vclock` driver closes on `stop`); `retryThrottled` returns `nil, err`; errors wrap with `%w` and are matched with `errors.Is`.
- **Isolation.** The global `processPacers` is touched only by zero-config tests with the instant `defaultSleep` or by tests that clean up their unique model keys; `-shuffle=on -count=5` on both packages was green.
