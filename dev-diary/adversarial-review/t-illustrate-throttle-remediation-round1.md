## Open items (for the orchestrator; not fixed because they are outside the seam)

1. **bookgen regression caused by H1's fix: needs a contract change.** `internal/bookgen/pipeline.go:59` builds `illustrate.Config{Imager, Judge, Persist, Progress}` with a zero `Throttle`, so the pacer really sleeps 31.5 s between the fake imager's calls in bookgen's tests. Fix belongs to bookgen's owner: add a `Throttle illustrate.ThrottleConfig` pass-through on bookgen's config/handler, set it to instant in the tests (`RequestsPerMinute: -1` or an injected `Sleep`), and wire the real per-minute figure from the model's config in `cmd/thutapi/main.go` when the port makes that a setting. The `illustrate` side needs nothing further. Until that lands the full `go test ./...` is red, so Definition of done item 5 is **not** met for this track. I did not touch bookgen: `AGENTS.md` item 7 and the seam rule forbid it.
2. **`internal/audio/audio.go:99`** still says "the only retry — this package adds no second layer", which `internal/audio/throttle.go` contradicts. Pre-existing, out of seam (the reviewer flagged it too). Follow-up for T8's owner.
3. **Judgement calls to look at in round 2.**
   - The pacer adds a 5% margin (30 s becomes 31.5 s at the default rate) for clock and network skew; the reviewer did not ask for it. A book of N images takes at least (N-1) x 31.5 s: an 8-page, 3-cast book is about 5.8 minutes of pure pacing, which the front end's "a few minutes" copy (`static/app.js`, T9's file) should know.
   - `defaultSleep` is still a package variable (read in `resolve`), kept so the test binary can make un-configured throttles instant. Reviewer M3's concern about a mutable global is reduced, not removed: production never assigns it and `realSleep` is tested directly.
   - The simulation's virtual-clock driver advances on real-time quiescence (about 2 ms). Late wake-ups can only make requests sparser, so the heuristic cannot hide a pacing bug, but retry jitter comes from the global `math/rand/v2` and is not seedable, so a seed fixes the scenario, not every random draw. I ran the two simulation tests with `-race -count=10` clean.
   - `ReferenceLimit` is kept (renamed in meaning only). With the pacer it no longer protects the rate cap; it is now purely an in-flight bound. Removing it would be an API change nobody raised.
